# Sword Showdown — AI Agent Quick-Start Guide

> **Maintenance rule:** When you add/remove/rename files, change module responsibilities, or alter the boot sequence, update this file and `CLAUDE.md` in the same commit. Accurate docs save tokens on every future task.

**Game name:** Sword Showdown (repo name `qwop-tps` is historical)  
**Type:** Browser-based 3D sword-fighting game; your phone is the sword (gyro controller via PeerJS). Modes: Tutorial, Showdown (single player), Classic (Wii-style Showdown: Miis, 3 hearts, Block only), Town (a living town of ~20 townsfolk with jobs, homes and a day / night clock and an economy of wood / fish / veg with a market; you start with nothing, gather, trade and buy your gear — or commit crimes and deal with wanted stars, guards who carry you to jail, bail / bribes / lockpicking; townsfolk hold grudges, call for help, fight each other and follow friends; bandits camp far out of town, raid at night and warn you off their camp; townsfolk hand out jobs — ❗ over whoever has one, ❓ when the reward's waiting — plus quest chains with a tracker) and Multiplayer (lobby + 1v1 sword duels; Team Battle 5v5 and Free For All, each as Survival or Most Kills, with matchmaking, bots and arena pickups).  
**Deep reference:** `CLAUDE.md` at repo root (architecture, patterns, full directory tree)

## Tech Stack (one-liner each)

- **Rendering:** Three.js v0.176 (+ `three-mesh-bvh` for map raycasts)
- **Physics:** Rapier3D (`@dimforge/rapier3d-compat`)
- **Multiplayer:** Multiplayer mode only (Showdown is single player). Firebase (`peers` = lobby list, `rooms` = lobby / private duel rooms / `mm-<mode>` matchmaking queue / `party-<hostId>` / `match-<matchId>`, shop stock) + PeerJS WebRTC; messages: `presence`, `projectile`, `duel`, `match`
- **World:** `public/mappacks/island_town.mappack` (via `src/map/MapLoader.ts`) for every mode but Classic (scaled ×1.4 via `MAPS.islandTown.scale` — map coordinates in code are scaled world units); Classic uses the static GLB map (`public/glb_map/map.glb`)
- **Auth:** PIN → SHA-256 → Firebase + cookie (no OAuth); the app opens as a guest (unless a stored PIN auto-logs in); "Sign In" on the start screen reloads to the login form (`sq:showLogin` sessionStorage flag); guest = random name, `profileNameKey` null, nothing saved (guard profile writes on `profileNameKey`)
- **Build:** Vite 6, deployed on Vercel

## Key Patterns to Know

**Feature facades** (`src/features/`): thin wrappers that re-export lightweight APIs and `import()` heavy modules lazily. When adding a heavy new feature, add a facade here to keep the initial bundle small.

**World:** `bootstrapGameApp.js` loads the map for the mode (`MAPS`: island town mappack, or `map.glb` for Classic — switched by `_setActiveMap` in the mode handler), builds a BVH and registers a raycast height resolver with `registerTerrainHeightResolver`; `getTerrainHeight` / `getSpawnY` use it.

**Stages:** `_psPickPathAngle` picks the flattest direction, `_psBuildStage` places enemies and coins along it, and the player auto-walks between fights. Enemies live in the `hordeEnemies` array (historical name).

**Character arms (GLB + IK):** Players use `village_boy.glb` (`glbCharacterConfig.villageBoyUrl`) by default; EnemyPlayers cycle `pumpkin.glb` / `antler_guy.glb` / `frog_man.glb` / `gemhorn_rigged.glb` / `wizard.glb` / `tree_creature.glb` per spawn (`url` option of `createGLBCharacterInstance`; same Mixamo skeleton). Mixamo FBX clips animate everything except the arm chains (Shoulder→Hand); each frame the arms are solved with a stretchy two-bone IK toward invisible "floating hand" groups, which are also the weapon attach points (marked with `userData.proceduralHand`). Frame order: `setMoving` → `animate` → `solveArm` per hand → `stepFluff`. Moving characters play `Slow Run.fbx` (`runClip`) instead of the walk above `glbCharacterConfig.runSpeed` (ground speed measured in `animate`, `_updateSpeed`). The player's dodge roll (a swipe on the touch screen — not while it is the gyro sword, "Use This Device", `swipeRollAllowed` — or the phone controller) plays `Roll.fbx` (`rollClip`) with `playAction` — `ROLL_CONFIG` / `startRoll` in `controls.js`, `tryPlayerRoll` in `bootstrapGameApp.js`. Floating-hand labels are mirrored: `'right'` sits at local +X = the character's anatomical left arm. Per-character weapon hold: `glbCharacterConfig.holdByUrl` (`characterHold(url)` → `{ grip, sword }`) scales the floating-hand grip targets in `updateProceduralPlayerRig` / `updateRemotePlayerRig` and the held sword (`FoamSword.update`, `createSwordMesh`) — village boy grips at 0.76 with a 0.8 sword. Which arms the IK drives is per hand (`GLBCharacter.setArmIKHands({ left, right })`, the clip animates the others and restarts to pick them up): the local player with nothing equipped has only the anatomical right arm (`'left'` hand) on the IK, following the phone gyro (`userData.gyroArmQuat` / `gyroArmTime`, set in the phone-sword gyro loop of `bootstrapGameApp.js`, `GYRO_ARM_*` in `playerModel.js`); with no live gyro both arms play the clip. `playDeath()` plays the flying-back death clip once (arms included, IK off) until `revive()` — used by the local player on death/respawn and by EnemyPlayer (ragdoll stays on; dead-enemy knockback capped by `DEATH_KNOCKBACK_CAP` in `EnemyPlayer.js`). The Sword Showdown bomb thrower (`BombThrowerEnemy.js`) uses the same GLB with `armIK: false` (clips drive the arms): `playAction(glbCharacterConfig.throwClip)` plays `Throw.fbx` once and the bomb is released at `THROW_RELEASE_AT` of the clip; between throws a bomb is held on the anatomical right palm (`getPalmWorldPosition('left')`). **Mii characters** (`mii1.glb`, future `mii2.glb`…, detected by `isMiiCharacterUrl`) have no shoulders/arms/hands: `solveArm` is a no-op, `getPalmWorldPosition` returns a point beside the body (`palmFallback`), and they hold the Wii sword (`wii_sword.glb`), whose instances carry two brown ball hands on the handle (`createSwordModelInstance({ characterUrl })` in `swordModel.js` — used by `FoamSword` (swaps with the player's character), `EnemyPlayer._buildSword` and `createSwordMesh` for duel/battle opponents).

**Start screen + tutorial:** "Start Game" runs the tutorial until `profiles/<key>/tutorialCompleted` is set; then the start screen offers Tutorial / Showdown / Classic / Town / Multiplayer (auth resolves at login so the game loads behind the start screen; picks go through `setModeHandler`, queued if the game isn't ready; `arcadeOverlay.showStartScreen`). The ⚙️ settings button is layered above the start screen, stage overlay and Multiplayer lobby, shown once `body.settings-ready` is set (in every mode, Classic included; the default map loads in parallel and is awaited only after that — `_defaultMapReady`). `src/tutorial/showdownTutorial.js` scripts enemies via `EnemyPlayer.script` and the bomber's `throwsHeld` / `aimAt`, and reaches the game only through `tutorialCtx` in `bootstrapGameApp.js`.

**Town mode:** `src/town/townMode.js` (`createTownMode(ctx)`; its parts live in `townLayout` / `townFolk` / `townLife` / `townLaw` / `townReactions` / `townBandits` / `townTrade` / `townMissions` / `townActs` / `townWire`, each `installTownX(T, ctx)` adding its functions to the shared object `T` — mutable town state is `T.x`, a function from another module is called as `T.fn()`; game access via the `town` ctx next to Dev Free Roam in `bootstrapGameApp.js`; `town.update` after `village.update` in the loop). Townsfolk are plain records (role, home, work spot, needs, money, attitude toward the player) driven by a utility "decide" (work in the role's hours / eat at the market / the campfire / sleep / wander) on a town clock (an hour = 20 s); they walk A* paths on a walkability grid sampled from the map (`townNav.js` — buildings are height steps, water and steep steps are out, roads are cheaper). Only the nearest `TOWN_MAX_BODIES` get a GLB body (pooled per model); someone fighting the player is swapped for an `EnemyPlayer` in `hordeEnemies` (`ctx.spawnFighter`, flagged `_town`) and back. Sword hits on townsfolk come from the phone-sword loop (`town.trySwordHit`); a hurt / killed townsperson is a crime only if someone sees it (`raycastMapSegment` line of sight; friends don't tell) → wanted stars, guards answer and fight; beaten or 🙌 Give up → BUSTED, fine, jail cell (`positionConstraint`) for a while or bail; not wanted → knocked out (`showGameOver` hands the death to `town.onPlayerDown`). The dead stay dead; newcomers move in. Economy (`townEconomy.js`): producers make wood / fish / veg and sell it to the merchant (paid from the merchant's own money), townsfolk buy food there, prices follow the stock; the player chops trees with the sword, fishes (a bought rod, swung like the sword: cast, hook, wear it out, reel — `townFishing.js`), picks veg (theft if seen) and trades at the market: two stalls (`townStalls.js` — goods / weapons + a mystery chest) bought from the Showdown village's way (walk up → 🧺 Goods / ⚔️ Weapons or tap a thing on a counter: the shop camera frames it, tap a thing for its buy card), selling in the panel (💰 Sell, `townMarketPanel.js`). Gear, coins and health: Town has its own (`startTownLoadout` / `endTownLoadout` / `grantTownItem` in `bootstrapGameApp.js`; the real items and the `TOWN_ASIDE_STATS` — coins, health, max health, XP… — wait in `_saveAside`, which saves write instead; the town's coins + health are saved with its items) — the player starts with nothing, buys even the sword, can put everything away (✋ Hands — `appState.putWeaponsAway`, phone `sword` action), and loses it all on an arrest; bullets / bombs / magic hit townsfolk via `town.getWeaponTargets` / `getMagicTargets`. Saved per profile in localStorage `town_<key>` (guests: memory).

**Shared Town (Multiplayer):** `src/town/townNet.js` gives each signed-in player a town room for good (Firebase `townHome` / `townRoomMembers`, at most `TOWN_ROOM_MAX`=15 members; a member away 3 weeks loses their place) and runs the PeerJS room `town-<roomId>`. The room's host (oldest peer) runs the townsfolk in `townMode.js` and sends their compact state (`npcs`), the clock + market (`w`) and the whole town (`full`, for late joiners and a new host); the world is saved in `townRoomState/<roomId>`. A player's game claims townsfolk it needs for its own player (fights, followers, fleeing, talk, guards after its crime — `take` / `release`), so fights run locally as in single player; hits on someone another game runs are sent there (`hit`), deaths to the host (`died` → `dead`), market trades / money as ops to the host. Wanted stars, attitude, jobs, goods and gear are each player's own (`town_mp_<key>_<roomId>`). Other players' swords are drawn and hittable (PvP, `pvp`); hurting a player who isn't wanted is assault, downing a wanted one pays a bounty. The next oldest peer takes over when the host leaves (`checkNetRole`); with no room (offline) it's a town of your own.

**Multiplayer (lobby + duels):** only in Multiplayer mode — `startMultiplayer`/`stopMultiplayer` in `bootstrapGameApp.js` create/destroy the `Multiplayer` instance, so `multiplayer` is `null` in Showdown/tutorial. Firebase `peers` = who's online (lobby list), `rooms` = `lobby` or `duel-<challengeId>` (`joinRoom`). `src/multiplayer/duelMode.js` runs the lobby, challenges (PeerJS `duel` messages via `sendTo`) and the duel (sword only, best of 3 rounds with 8 health each, 3-2-1-FIGHT, both walk in toward each other, attacker-detected hits, `dead {round}` scores the round, WINNER banner, back to lobby); it reaches the game through `duelCtx`. Duel spot = `DUEL_LOCATION` in `duelMode.js` (the same point as `ARENA_LOCATION`). The lobby's Team Battle / Free For All cards (each with a Survival and a Most Kills button) hand over to `src/multiplayer/matchMode.js` (lobby `suspend`/`resume`): party setup with a rule picker, invites and side/character picks, Start pulls players waiting in `mm-<mode>-<rule>`, bots fill up to 10 (host-simulated `EnemyPlayer`s fighting with the boss fighter logic and whatever they pick up), battle in `match-<matchId>` around `ARENA_LOCATION`; Survival = last team / fighter standing, Most Kills = respawns, most kills when the clock runs out (or at the kill target) wins; game access via `matchCtx`. Everyone starts with the sword; pickups scattered around the arena (`src/multiplayer/matchPickups.js`, granted by the host) give guns, bullets, shields, bombs, wands, mana, hearts, life potions and bubbles — the real inventory is set aside and nothing is saved meanwhile (`matchCtx.startMatchLoadout`); whoever fires / throws detects the hits (host for bots) and sends `hit` / `botHit`; every hit names its attacker, the host counts kills (`kill`). The phone controller has its own PeerJS link.

## Boot Sequence

`index.html` → `app.js` → `bootstrapGameApp.js`:
1. Three.js scene + renderer
2. Rapier physics world
3. Firebase + player profile
4. Default map (island town mappack) + height resolver (started here, awaited after the settings panel — `_defaultMapReady`)
5. Character spawning
6. Phone controller link (peer multiplayer starts only in Multiplayer mode)
7. `requestAnimationFrame` loop starts

## What NOT to Do

- Don't bypass `appContext` with `window.*` globals in new code
- Don't import heavy modules at top level — use the facade pattern (`src/features/`)
- Don't modify `public/service-worker.js` cache list without bumping the cache version
- Don't add game logic to `src/core/` (infrastructure only)
